# Mini LLM - Character Tokenizer

A simple character-level tokenizer built from scratch as part of the **Mini LLM project**.

The goal of this project is to understand the fundamental building blocks behind Large Language Models (LLMs) by implementing each component step-by-step, starting with tokenization.

---

# Overview

Before a language model can process text, it must convert human-readable text into numerical representations.

LLMs do not directly understand:

```

hello world

```

Instead, text is transformed into tokens:

```

hello world

```
    ↓
```

[7, 22, 16, 32, 21]

```

These token IDs are then passed into neural network components such as embeddings and Transformers.

This project implements a simple **character-level tokenizer** that performs:

```

Text
|
v
Tokenizer
|
v
Token IDs
|
v
Decoder
|
v
Text

```

---

# Features

Current implementation includes:

- Character-level tokenization
- Vocabulary creation from training text
- Token-to-ID mapping
- ID-to-token mapping
- Text encoding
- Token decoding
- Unknown token handling (`<unk>`)
- Text normalization (lowercase conversion)
- Vocabulary size tracking
- Save/load functionality
- Built-in sanity checks

# How It Works

## 1. Training the tokenizer

The tokenizer learns a vocabulary from sample text.

Example:

Input:

```

hello world

```

Vocabulary:

```

<unk> → 0
(space) → 1
h → 2
e → 3
l → 4
o → 5
w → 6
r → 7
d → 8

```

The vocabulary is created from the unique characters found in the training data.

---

## 2. Encoding text

Text is converted into token IDs.

Example:

Input:

```

hello

```

Output:

```

[2,3,4,4,5]

```

Each character is replaced by its corresponding vocabulary ID.

---

## 3. Decoding tokens

Token IDs can be converted back into text.

Example:

Input:

```

[2,3,4,4,5]

```

Output:

```

hello

```

---

# Unknown Token Handling

If the tokenizer encounters a character that was not present during training, it replaces it with:

```

<unk>
```

Example:

Training data:

```
hello world
```

Input:

```
ChatGPT
```

Characters not found in the vocabulary become:

```
<unk>
```

This prevents the tokenizer from crashing when it sees unseen characters.

# Design Philosophy

This project intentionally starts with a simple implementation before introducing more advanced techniques.

The learning progression is:

```
Character Tokenizer
        |
        v
Word Tokenizer
        |
        v
Byte Pair Encoding (BPE)
        |
        v
Transformer Model
        |
        v
Mini LLM
```

# Why Build a Tokenizer From Scratch?

Modern LLM libraries hide tokenization behind APIs.

This project aims to understand what happens underneath:

```
Human Language
        |
        v
Tokenizer
        |
        v
Numbers
        |
        v
Neural Network
        |
        v
Predictions
```

Understanding tokenization is essential for understanding how models such as GPT-style architectures process and generate language.
